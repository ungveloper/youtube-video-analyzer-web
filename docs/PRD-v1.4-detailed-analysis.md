# PRD v1.4 — 상세 분석 및 가독성 개선 (2026-10-08)

## 배경

개인용 무료 Gemini API 모드에서 3분 22초 영상의 분석은 성공했으나 출력 토큰 1,245개로 핵심 요약 1개, 뭉뚱그린 타임라인, 간략한 아티클이 생성됨. 이전 코드의 `max_output_tokens: 10000`은 **상한값**이지 반드시 해당 분량을 생성하라는 의미가 아니므로 프롬프트 품질 목표와 화면의 정보 구조를 개선.

## v1.4 정책

- `gemini-3.5-flash-lite` 유지, 무료 API 호출 기본 1회 유지. 상세함을 위해 2차 API 호출을 자동 실행하지 않음.
- 동영상 길이에 따른 편집 목표: 5분 이하 요약 4/타임라인 6/아티클 4, 15분 이하 5/9/6, 그 이상 6/12/8. **숫자는 목표이며 근거 없이 강제하지 않음.**
- 모든 핵심 주장에 영상 근거 ID 필수. 시간값 범위 검증 유지, 영상 내용과 의미적 일치는 사용자의 원본 확인 필요.
- 요약: 항목별 2~4문장, 타임라인: 주제 변환 시점별 2~4문장, 아티클: 소제목 아래 가능하다면 여러 개의 서로 다른 설명 문단.
- 입력 영상에 실제로 없는 수치·의학적 결론·사례를 추가하지 않음. 주장인지 검증 사실인지 분명하게 표현.
- 출력 토큰 허용 상한 16,000(사고 토큰 포함), `thinking_level: low`. 모델별 한도·사용자 무료 티어·영상 길이에 따라 결과 밀도는 달라질 수 있음.
- 결과 분량이 짧으면 화면에 진단 문구를 표시하지만 **추가 AI 요청이나 비용 사용은 하지 않음**.
- 기존 브라우저 IndexedDB 결과는 자동 수정하지 않고 그대로 유지. 새 분석 버튼은 새로운 무료 API 호출을 수행함.
- 요약은 번호 카드, 타임라인은 시각 순 정렬과 근거 링크, 아티클은 소제목·문단 중심 레이아웃. 네 탭 모두 편집·복원·다운로드 유지.
- 분석 로그에 각 탭 항목 수, 아티클 문자 수 및 얕은 결과 필드를 추가. 원본 영상 전문이나 API 키는 로그에 기록하지 않음.

## 검증 절차

1. `npm run lint -- --max-warnings=0`와 `npm run build` 통과.
2. `npm run dev -- --hostname 127.0.0.1` 후 기존 분석 기록을 연 상태에서는 이전 결과가 남아 있음을 확인.
3. 무료 API 남은 한도를 확인한 후 `다시 분석` 실행. 실제 영상에서 4개 이상의 상이한 핵심 주장 여부, 타임라인 시간 일치, 아티클 구성, 스크립트 추측 여부 수동 점검.
4. 터미널 `analysis.completed` 로그의 `outputTokens`, `contentMetrics`, `shortFields`를 이전 결과와 비교.
5. 본 프로젝트의 완료된 콘텐츠·편집 결과는 IndexedDB에만 저장, Redis·DB 미사용. Gemini 무료 등급 프로젝트 직접 확인 조건 유지.
