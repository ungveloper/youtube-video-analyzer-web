# v20 — 원문형 시간 지정 타임라인

## 기존 문제

기본 URL 분석은 AI가 문장의 표현과 시각을 동시에 만들어 사용자가 전사로 받아들이기 쉬웠습니다. 정밀·자막 경로에서는 AI가 생성한 타임라인이 사용자가 붙여넣은 원문의 정확한 표현을 재작성했습니다. 마지막 타임라인의 *시작* 시각이 영상 종료보다 이르다고 경고하는 것도 잘못된 단정이었습니다.

## 정책

- **사용자가 제공한 시간 지정 자막:** `sourceFromUserCaptions`가 구간을 만들고 `timelineFromProvidedCaptions`가 모든 근거 문장을 그대로 사용합니다. 모델이 작성한 타임라인은 버립니다. 실제 원문의 시간과 문장에 대해 모델이 새 수치, 추가 발언, 의학적 평가를 넣을 수 없습니다. 장문의 자막이 일정 시간/문장 경계로 합쳐질 수 있으나 문장 내용은 보존합니다. 스크립트 탭은 입력 자막의 개별 큐를 계속 보여줍니다.
- `[0:00] 발언` 등 대괄호 형식 입력도 파싱합니다. 타임스탬프만 있는 마지막 자막의 종료시각은 알려지지 않았으므로 영상 끝으로 무단 확장하지 않습니다. 해당 cue는 `end=start`로 표현합니다.
- **URL만 제공:** 단일/정밀 분석 모두 발언의 어순을 유지하도록 강화하지만 Gemini 결과는 녹취 검증이 아니며 AI 초안임을 명시합니다. 시각 오류는 사용자가 영상과 대조/수정해야 합니다.
- **후반부 검사:** 마지막 행의 시작시각이 아니라 수집된 근거 *종료* 기준으로 검토 경고를 표시합니다. 임의로 03:22에 타임라인 행을 추가하지 않습니다. 충분한 근거가 없는 경우 누락 가능성을 그대로 표시합니다.
- 무료 API 호출은 기존과 동일합니다. 자동 자막 다운로드나 온라인 자막 수집은 하지 않습니다.

## 회귀 테스트

`tests/verbatim-timeline-regression.mjs`에서 자막 문장 보존, 모델 작성문 대체 금지, 대괄호 타임스탬프, 마지막 cue의 미확인 끝시각 처리, 시작시각 02:48/종료시각 03:18 시 경고 억제를 검증합니다.
