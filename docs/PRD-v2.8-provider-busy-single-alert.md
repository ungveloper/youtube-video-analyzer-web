# v21 — Gemini 503 회복 및 알림 단일화

## 배경

Gemini 3.8 Flash가 HTTP 503 high demand를 반복하는 동안 기본 분석에는 재시도가 없었고, 동일 오류가 화면의 failure 및 message, Sonner 실패 토스트에 세 번까지 보였습니다. 서버 과부하는 앱 코드만으로 해소할 수 없습니다.

## 사양

1. HTTP 503은 `PROVIDER_BUSY` 코드와 간결한 안내를 사용한다. 원시 API 오류/키를 UI에 전달하지 않는다. 429는 `FREE_LIMIT`로 즉시 중단한다.
2. `retryOnBusy`는 사용자 설정으로 기본 true. 기본 분석과 정밀 추출의 503에 한해 2.4초 대기 후 딱 한 번 재시도하며, 취소하면 추가 호출하지 않는다. 정밀 분석의 기존 500·504 복구는 유지한다. 재시도 후에도 503이면 종료한다. 추가 무료 API 요청 가능성을 명시한다.
3. 기존 화면 진행상태가 이미 있으므로 analysis 전용 무한 로딩 Sonner를 제거한다. 실패 상세는 한 곳(화면 `role=alert`)에만 렌더링한다. 중단 시에는 짧은 Sonner만 표시한다.
4. 앱 내 성공·다운로드·편집 알림 등 Sonner 기능은 유지한다. 기존 UI 컬러·우측 하단·최대 5개 설정을 보존한다.
5. 테스트 대상: 503 단일 재시도·중단·429 금지·설정 입력 검증·중복 알림 금지.

## 미해결

Google의 503이 장시간 지속되면 한 번의 재시도로도 성공하지 못한다. 처리 성능 향상이나 5초 완료를 보장하지 않으며, 실제 Google 연결 테스트는 사용자 Mac에서 필요하다.
