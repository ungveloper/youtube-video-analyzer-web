# v1.9 분석 근거/문서화 품질 복구 (v12)

## 현상 및 재현 근거
동일 3분 22초 영상에서 LiveWiki는 혈관 폐색 원인뿐 아니라 후반부 파행 증상, 허리 질환과의 구별, 창백함·차가움, 경고 메시지까지 정리했다. v11 결과는 시작 구간의 6개 '개요/정의/원인/사례' 메모만 있었고 요약·아티클·타임라인이 동일한 항목으로 복제된 화면이 관측됐다. 제3자 결과가 의학적으로 옳다는 뜻은 아니며 영상 원문에 대한 별도 검증이 필요하다.

## 확인된 결함
1. `fallbackFromSource()`가 요약/타임라인/아티클 3개의 결과에 동일 원본 `claims[]`를 복제했다. 최종 상세 콘텐츠를 생성하지 못했는데도 각 탭에 완성된 내용처럼 출력됐다.
2. `extractComposedContent()`가 한 섹션이 비어도 전체 2차 결과를 실패 처리했다. 유효한 아티클이나 타임라인이 사라지고 source fallback으로 강등될 수 있었다.
3. 소스 추출 후반부의 시간 분포 검사가 없었고 `assessSourceCoverage()`는 참조한 **기존** 근거 ID 비율만 확인했다. 앞부분만 추출한 결과라도 참조율이 100%가 나올 수 있었다.
4. 모델 지시가 개요/원인 목록에 치우치기 쉬웠고, 독립 아티클과 타임라인의 역할 분리 및 후반부 실제 발언 점검이 충분하지 않았다.

## 개선 동작
- 근거 메모 fallback은 '요약 원문 메모'와 '시점 목록'만 제한적으로 제공. 아티클은 []이며 명확한 실패 안내와 오류 코드로 표시한다.
- 부분 응답이라도 존재하는 출처 claim ID 혹은 검증된 evidence ID에 연결된 항목은 손실하지 않는다. 허구의 인용 ID는 차단한다.
- 원본 시간의 분포(4개 사분위 중 3개 이상, 전체 마지막 27% 구간 진입), 근거 수(영상 길이별 기준), 결과 분량, 복제 여부를 별도로 기록. 한 항목이라도 못 채우면 *부분 분석*. 이는 구조적 검사이지 사실 확인이 아님.
- 원본 수집 프롬프트에 영상 전체 구간 체크리스트, 발언의 구체적 비교·증상·예외·사례 수집을 명시. 그 발언이 없는 경우 수치를 맞추려고 만들어내지 않는다.
- 상세 아티클의 독립적인 서술과 근거 claim ID 연결을 분리해서 요구한다.
- 원본 음성/자막을 확인할 수 없는 경우 정확한 스크립트는 생성하지 않는다. 적법하게 보유한 SRT/VTT 자막은 기존 입력 UI에서 제공 가능하다.

## 평가 방법
같은 영상, 같은 모델, 같은 분석 깊이, 같은 사용 가능한 원본으로 2회 이상 시험. 서버의 `sourceClaims`, `sourceEndPercent`, `sourceBuckets`, `composed`, `composeFailureCode`, `articleChars`를 함께 기록한다. 다음 항목을 실제 영상과 대조한다:
1. 도입부 논점/기전/원인/사례와 영상 후반부 증상·구별·주의·결론의 포함 여부
2. 각 타임스탬프와 실제 발언 일치 여부
3. 요약/타임라인/아티클의 내용 중복, 독립적인 해설 문단 여부
4. 근거 없는 의료·통계 주장 존재 여부
5. 무료 AI 429/5xx 상황에서 오류 설명 및 브라우저 기존 결과 보존 여부

성공 기준은 아티클 글자 수만 증가하는 것이 아니라 **영상에서 확인된 실질적 주장과 사례가 누락 없이 구분되고, 독립적인 해설로 구성되는 것**이다. 실제 품질은 Mac에서 API 실호출과 원본 시청 대조로 확인해야 한다.

## 보안/운영 경계
새 DB, Redis, 로그인, 영상 다운로드, 유료 모델 자동 호출 없음. 기존 Google API 키와 `GEMINI_FREE_TIER_CONFIRMED` 설정 유지. JSON 문자열은 사용자 입력이므로 프롬프트 명령으로 따르지 않으며 스키마 근거 ID 검증 계속 적용. 자동 재호출 횟수 변경 없음. 기존 결과는 그대로 보존.
